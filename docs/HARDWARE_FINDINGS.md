# Первичная проверка MoGo — 2026-10-04

Проверено на физическом XGIMI MoGo 3 Pro G0035. Личные идентификаторы, сетевые адреса, снимки и сырые логи в этот файл не включены; диагностика остаётся в игнорируемом `device-diagnostics/`.

- Android 14, API 34. Система объявляет **только `armeabi-v7a,armeabi`**. В APK добавлена Rust-библиотека ARMv7; ARM64 сам по себе этому устройству не подходит.
- OpenGL ES 3.2; максимальная текстура 8192. Приложение использует GLES 2-совместимые шейдеры.
- Встроенный Rust/Axum отвечает по Wi-Fi; HTML и JavaScript визуального редактора отдаются проектором.
- QR прочитан из кадра устройства, сопряжение прошло. Управление редактором на реальном сервере проверено в изолированном Chromium через временный ADB-forward; открытие в Safari на iPhone пока не проверено.
- Выбранная из Met картина Ван Гога скачалась в приватное хранилище MoGo. Перетаскивание в браузере изменило сохранённые координаты. Фактический OpenGL-кадр устройства подтверждает картину в новом положении.
- Сцены с 0, 1, 3, 6 и 12 областями приняты устройством. Для видео показаны два отдельных H.264 SDR 1920×1080/30 MP4 одновременно с тремя картинами. Это краткая проверка, а не часовой тест стабильности.
- В первоначальном видеошейдере обнаружена перевёрнутая видеотекстура. В код добавлена коррекция вертикальных координат перед матрицей SurfaceTexture. Исправление установлено через update; кадр устройства сверён с исходным MP4, ориентация подтверждена. Два аппаратных декодера объявили `OMX.MS.AVC.Decoder`.
- Во время краткого показа двух видео наблюдался PSS примерно 115–132 MiB. По GL-агрегату одной сессии: 4183 отрисовки, 20 отрисовок дольше 33,3 мс, среднее CPU-время отрисовки 9,586 мс. Это не измерение полного frame pacing; итоговые dropped frames, тепловая стабильность и часовой тест ещё не подтверждены.
- Back штатно закрыл приложение и HTTP-порт; повторный запуск восстановил сохранённую музейную сцену.
- DreamService, автоматический простой и невмешательство в KinoPub/HDMI пока не проверены физически.

Установка выполнена через `adb install -r`. Системные настройки питания, яркости, сети, HDMI и учётных записей не менялись. Другие приложения не удалялись и их данные не очищались.

Полный сценарий оставшихся проверок: [DEVICE_VALIDATION.md](DEVICE_VALIDATION.md).

## Исправление входа браузера

Добавлен шестизначный код для компьютера на экране QR. Основной адрес приложения закреплён на порту 8787 с резервным свободным портом при конфликте. Cookie и авторизованные сессии хранятся 30 дней; сессии записываются атомарно отдельно от SQLite галереи. Неверные попытки ввода кода ограничены. Вход по коду, перезагрузка страницы и повторный вход без QR после штатного закрытия/повторного запуска приложения подтверждены в браузере на физическом MoGo. Состояние недоступной сети теперь отличается от запроса сопряжения.

## Ускорение редактора и постоянный код

В коде убраны повторные загрузки статичных текстур на каждом кадре видео, дублирующие загрузки одного медиа для нескольких областей и обновление всего каталога при drag. Кадры видео обновляются через requestVideoFrameCallback, геометрия — через requestAnimationFrame; статичная сцена и пауза не запускают постоянный цикл рисования. Проверено браузерными тестами с реальным MP4 и 12 областями с общим изображением. Селект сцен заменён кнопками с миниатюрами композиции. Ключ подключения хранится отдельно от галереи и не меняется при сопряжении, Menu или перезапуске.

## Готовая коллекция обоев

В приложение добавлены 12 оригинальных динамических циклов H.264 SDR 1280×720/30 и 12 статичных абстракций. Шесть динамических вариантов относятся к киберпанку. Файлы входят в APK, выбор и импорт работают без интернета. Классические картины остаются отдельной вкладкой. Предпросмотр каталога проигрывает один ролик за раз; браузерный кадр использует уменьшенные видеотекстуры, а проектор получает исходный файл.

Предварительная проверка производительности через сервер физического MoGo подтвердила одну загрузку общего изображения при двух видеопревью; значения частоты кадров тестового Chromium с программным GPU относятся только к этому окружению, а не к Safari или браузеру пользователя.

Финальная коллекция установлена и проверена через сервер реального MoGo: доступны 12 динамических вариантов и 6 в фильтре «Киберпанк»; выбор «Кибергорода» создаёт локальный видеоресурс `polotno:7` без загрузки своего файла. Ошибок JavaScript в проверенном сценарии нет. Проверка UI устройства после подключения подтверждает отсутствие QR-приглашения. Перед временной проверкой сохранялась исходная композиция; после неё восстановлен исходный предпросмотр.

## Рамки, сетка и расширенный импорт

На физическом MoGo подтверждены калибровочная сетка новой области и розовая неоновая рамка с внешним свечением. MOV/ProRes и MKV/FFV1 проходят автономное преобразование в H.264 MP4; оригиналы доступны отдельным скачиванием. Вертикальные кадры сохраняют пропорции в режиме «Целиком». Энкодер MediaCodec прошивки в проверке давал пустой вывод; рабочий резерв — встроенный OpenH264. Для PNG и фото-превью в сборку конвертера явно включена системная zlib.

Финально проверены на физическом MoGo: MOV/ProRes, MKV/FFV1, BMP, TIFF и HEIC. Результат — H.264 MP4 для видео и PNG для фото; оригиналы доступны и совпадают по содержимому с загрузкой. Для всех пяти форматов созданы превью. Превью обоих загруженных пользователем Dil Studio роликов также готовы. Исходная композиция восстановлена после калибровочного теста, временные файлы конвертера вне галереи удалены. Не заявляется поддержка всех возможных закрытых/защищённых кодеков.

## Видеоплейлисты без ограничения количества

По уточнению пользователя снят программный лимит двух видеоплейлистов в редакторе, Rust и Android. Один активный файл разделяет видеотекстуру и декодер между областями; интервалы выбора элементов плейлистов остаются независимыми. Включён Media3 decoder fallback. Неиспользуемые проигрыватели освобождаются.

На физическом MoGo кратко показаны четыре и шесть разных встроенных роликов, а также один ролик в двенадцати областях. Две последовательные аппаратные снимки подтверждают изменение содержимого каждой области. PSS в этих трёх сценах составлял примерно 96, 98 и 69 MiB соответственно. Пользователь заметил тяжёлое воспроизведение шести разных видео; логи подтвердили пропуски кадров (в отдельных интервалах 50 за 5,3 с и 130 за 2,7 с). Это подтверждение возможности назначения и показа, а не плавности шести потоков или длительной стабильности.

После проверки добавлено объединение видеособытий через Choreographer: все ролики инициируют одну отрисовку сцены с частотой до 30 кадров/с. Совместимые H.264 SDR до 1080p/30 с AAC или без аудио импортируются через remux, сохраняя меньшую частоту кадров и избегая повторного программного кодирования. Для более тяжёлых форматов остаётся нормализация. Долгий тест шести разных видео после этих изменений не проводился.

На MoGo добавлен подготовленный для нескольких областей ролик H.264 854×480/20. Повторное чтение сохранённого файла и FFprobe подтвердили сохранение 20 fps после быстрого импорта; ранее нормализация повышала лёгкие ролики до 30 fps.

## Зеркальное отражение

Добавлены независимые настройки горизонтального и вертикального отражения содержимого каждой области. Они применяются к фото и видео в GLSL; углы области, рамка, исходный файл и общий декодер остаются прежними. Поля сцен имеют значения по умолчанию для чтения старых JSON без миграции SQLite.

На физическом MoGo проверены обычный показ, горизонтальное, вертикальное и комбинированное отражение для PNG и H.264: восемь областей с одной общей картинкой и одним общим роликом. Сравнение цветов в 32 точках аппаратного снимка подтвердило все варианты. После проверки исходная пользовательская композиция восстановлена. В браузере проверены реальные пиксели обоих типов медиа, независимость соседней области и сохранение/повторное открытие сцены.
